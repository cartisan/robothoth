## Overview
![[Pasted image 20260916135138.png]]

## 1. Define the outcome
- Engineer/PM specifies the problem and desired outcome
- Judgment, prioritization, and taste are becoming more important
## 2. Gather context
- Documentation lives inside the source code, easier for agents to understand
- Codex has access to Git/GitHub, Slack, Notion
- Access to internal data sources: Databricks, Datadog, internal logs
## 3. Implement code changes
- Codex works through changes until the goal is reached
- Verifies the software works as expected afterward
## 4. Build, test & CI
- Agent builds the code, runs tests, fixes code on failure
- Creates a pull request and babysits it until "green"
- Fixes CI failures and updates the PR automatically
- New: "perf harness" sends risky PRs to the Synthetics A/B framework for performance evaluation
## 5. Agentic code review
- Multiple agents with "domain specialist" configuration instead of one generic reviewer
	- Comparable to review by a human domain expert from each infra team
- Domain agents have full access to code/docs, giving targeted feedback
- Code changes are classified by risk
- High-risk: stricter processes (more AI reviews, possibly human review)
- Low-risk: auto-approval possible, improving velocity
- Agent handles review comments just like CI failures
## 6. Agentic deploy
- After human approval, an agent handholds the rollout
- Agent handles both code changes and feature-flag changes
	- Reads codebase, finds the feature flag, understands the change
	- Decides which signals indicate success/failure
- Builds its own monitoring dashboard
	- Watches production signals and dashboards
## 7. Observe production
- Uses dashboards generated by agents
- Uses internal observability stack (logs, metrics, traces, wide events)
## 8. Feedback into development
- "Perf Factory" uses agents to sift through alerts/dashboards
	- De-duplicates signals, identifies real latency regressions
	- Root-causes issues and proposes fixes
- Extends the workflow beyond deployment into continuous improvement
## 9. Respond to outages
- "Sevbot" is the internal incident response agent, built on Codex
	- Collects context about the incident
	- Determines possible mitigations (never executes them)
	- Answers questions in the Slack channel
	- Engineer can instruct a specific mitigation
	- Goal: autonomous handling of routine outages without waking humans
